# @getbrevo/brevo v2 → v6 Migration

`@getbrevo/brevo` v6 is a complete SDK rewrite generated by Fern from the Brevo OpenAPI spec.
The v2 class-based API is gone entirely.

All changes are in **`app/lib/send-in-blue-transactional.js`**.
The two test files (`lib/__tests__/send-in-blue-transactional.js` and
`lib/__tests__/brevo-transactional.js`) mock the SDK; verify they still pass after the changes.

---

## 1. Initialization

**v2**

```js
const Brevo = require('@getbrevo/brevo')
SibSMTPApi = new Brevo.TransactionalEmailsApi()
SibSMTPApi.authentications['apiKey'].apiKey = brevoApiKey
```

**v6**

```js
const { BrevoClient } = require('@getbrevo/brevo')
SibSMTPApi = new BrevoClient({ apiKey: brevoApiKey }).transactionalEmails
```

No `authentications` object exists in v6; the key is passed to the constructor.

---

## 2. Request objects — no more SDK classes

v2 required instantiating SDK model classes before populating them.
v6 takes plain objects.

**v2**

```js
let smtpTemplate = new Brevo.CreateSmtpTemplate()
smtpTemplate.templateName = name
// ...
const { body: data } = await SibSMTPApi.createSmtpTemplate(smtpTemplate)
// data === { id: 42 }  — numeric template ID

let sendSmtpEmail = new Brevo.SendSmtpEmail()
Object.assign(sendSmtpEmail, props)
SibSMTPApi.sendTransacEmail(sendSmtpEmail)
// props shape (from send-password.js):
// { to, sender, templateId, tags, params }
```

**v6**

```js
const data = await SibSMTPApi.createSmtpTemplate({ templateName: name, ... })
// data === { id: 42 }  — same shape, no change needed at the call site

SibSMTPApi.sendTransacEmail({ ...props })
// props shape is unchanged: { to, sender, templateId, tags, params }
```

**One instance, multiple templates:** `templateId` is a per-call property of the request object in both v2 and v6 — it is not set on the client instance. A single `SibSMTPApi` can send to any number of templates by passing a different `templateId` each call. No change in behaviour.

---

## 3. Response shape — no `body` wrapper

v2 methods resolved to `{ response, body }`.
v6 methods resolve directly to the data (via `HttpResponsePromise.unwrap()`).

| Call site            | v2                                                                    | v6                                                          |
| -------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------- |
| `createSmtpTemplate` | `const { body: data } = await api.createSmtpTemplate(...)`            | `const data = await api.createSmtpTemplate(...)`            |
| `getSmtpTemplates`   | `const { body: { templates, count } } = await api.getSmtpTemplates()` | `const { templates, count } = await api.getSmtpTemplates()` |
| `sendTransacEmail`   | `.then(({ body }) => ok(body))`                                       | `.then((body) => ok(body))`                                 |

---

## 4. Method signatures for `update` and `delete`

v2 took positional args. v6 takes a single request object with `templateId` as a property.

**v2**

```js
SibSMTPApi.updateSmtpTemplate(id, { isActive: false })
SibSMTPApi.deleteSmtpTemplate(id)
```

**v6**

```js
SibSMTPApi.updateSmtpTemplate({ templateId: id, isActive: false })
SibSMTPApi.deleteSmtpTemplate({ templateId: id })
```

## 6. Verify

```bash
npm test
```

All 14 suites should pass. The brevo test files mock the SDK so no live API key is needed.

To exercise the live API, set `BREVO_API_KEY` and `BREVO_DEFAULT_FROM_EMAIL` and run:

```bash
node --inspect-brk node_modules/jest/bin/jest.js --runInBand --config ./jest-db.config.js \
  --runTestsByPath app/lib/__tests__/send-in-blue-transactional.js
```
